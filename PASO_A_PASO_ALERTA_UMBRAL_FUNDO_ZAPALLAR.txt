PASO A — Cargar umbral (threshold)
================================================================================

En Swagger:
  Método:  PUT
  Nombre:  Agregar configuración de Threshold de alerta un nodo existente
  Ruta:    /configuration/companies/{companyId}/nodes/{nodeId}/threshold

Parámetros:
  companyId  = 000027
  nodeId     = (el punto, ej. 000027-08)

Nombre del body:  thresholdRequest

Contenido del body (ejemplo Etapa N°3):
{
  "threshold": "41.3"
}

Repetir por cada nodeId con su valor de la tabla de arriba.


================================================================================
PASO B — Agregar correo a la alerta
================================================================================

IMPORTANTE: el tipo de alerta es siempre FILTRATION (no LEAK).

  FILTRATION  → alerta de consumo / umbral diario + correos  ← ESTA
  LEAK        → otro esquema de fuga (en Zapallar no está configurada)

En Swagger (si la alerta ya existe — caso habitual):
  Método:  PUT
  Nombre:  Agregar usuario o un grupo de usuarios a una alerta existente
  Ruta:    /configuration/companies/{companyId}/alert/nodes/{nodeId}

Si el punto NO tiene alerta todavía:
  Método:  POST
  Nombre:  Crear una nueva alerta de configuración a un nodo existente
  (misma ruta)

Parámetros:
  companyId  = 000027
  nodeId     = (el punto, ej. 000027-01)

Nombre del body:  addAlertRequest

Contenido del body (igual para todos los puntos):
{
  "alertType": "FILTRATION",
  "notifyTo": [
    "anibal.aoperaciones@wes.cl"
  ]
}

Notas:
  - El "string" del ejemplo de Swagger es solo placeholder: reemplazarlo por el correo.
  - El PUT AGREGA el correo; no borra los destinatarios del cliente (LGA) que ya están.
  - NO hace falta tener los nodos 000027-* en allowedNodes del usuario para recibir el mail.
    Acceso en la app (allowedNodes) y suscripción al correo (notifyTo) son cosas distintas.
